- A source is one thing you read, at the grain you read it, at one revision: a file, a folder read as a listing, a pull request, a page, a ticket, or a search, whose coverage is a search hit. kind starts with one of: {{groups}}, then any detail, such as "tracker: epic" or "code: pull request". reference is a link, pinned to its revision for code, or for a search {"query": "<the exact query>"}. revision is the commit for code, the last-edited date for a page (YYYY-MM-DD), the status for a ticket, the date it was run for a search. coverage is an object whose read is one of: {{coverage}}. A partial read names exactly what was read, so that with the revision anyone can find it again: a document names its sections, {"read": "partial", "sections": ["Decision"]}, also one kept in a repository, such as a decision record or a README, which is documentation, at the commit; a code file names its lines, {"read": "partial", "lines": [[1, 80], [200, 240]], "of": 352}; a pull request or a folder names the files read, "files": [...]. A pull request read only by its description and its list of files is a listing, as is a folder whose files you didn't open. note adds anything else, such as why a source can't be accessed: {"read": "can't access", "note": "not on the main branch at this commit"}, for a path you looked for and didn't find. Only a {{read_coverage}} read establishes what code does. superseded_by is left out, unless another source replaces this one: then it names that source.
- A finding is one claim, in your words, of about 80 words at most: a topic with ten facts is ten findings. It says what the evidence shows, not what you conclude from it; a conclusion is a finding of its own, whose sources are the findings it rests on ([[f1]], [[F07]]). sources names where it was read, with a precise location where needed, such as "[[s1]] (lines 120-160); [[S04]]". limits says what the claim leaves out, including a contradiction with another finding, citing it, or None. partial gives, for each source the finding cites that was read only in part, why the part left unread can't change this claim, or that another finding covers it, citing it: {"[[s1]]": "the unread lines are admin routes"}; leave it out when there is none. A reason given for another claim doesn't carry over: if you can't give one for this claim, read the rest first.

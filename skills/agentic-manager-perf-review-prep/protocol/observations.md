# Summarise what is going well, what to improve and the context

A manager is preparing a performance review of the person named below. Other agents read the manager's notes, the person's Slack messages and the feedback and reviews the person received in the period, and turned them into points, each of what is going well or what to improve grouped under the company value it shows most. The report shows them as three tables, what is going well, what to improve and the context. Write a summary of each table, which the report shows above it, the table folded below as the detail: the manager reads the summary first, to see the picture without going through every point.

## What to read

The brief, at the path below, holds all you need: the person, the company's values with what each means, `focus`, where most of the person's pull requests and resolved issues went, and each table's points in its order, each with its source and when it was seen and, in going well and to improve, the values it names, the first the one it is grouped under. Read nothing else.

## How to write a summary

- Say what the person did, as behaviours, from the table's points alone, and how they show the company values: name a value inside the sentence, as the brief names it, such as "reflecting Ownership", never as a label or a list.
- Open with the person's main contribution, then go down to the rest. Judge it by how often a theme comes back across the points and by `focus`: a measure of volume, not of impact, so it orders what the points say and adds nothing they don't. The table orders points by value, not by weight, so don't follow its order.
- In going well and to improve, touch on every company value the table groups points under, the first of a point's `values`, even in a few words, or sharing a sentence with others, for one with few points: the script checks each is named. A value a point names second is a weaker signal: name it only where it adds something.
- Give each theme a paragraph of its own, the main contribution first. Don't give each value a sentence of its own, or name one where it doesn't fit.
- Say once what several points, or several sources, show together. A detail of one moment comes only as an example, one or two that show what the contribution was, never a list to fill the room.
- A point that changed over time stays as the points put it: in going well, since when it holds; in to improve, when it held. Weighing one against the other isn't yours to do.
- In to improve, say what was seen, what the person should do, and how progress would show, as the points give it.

- Write about {{observations_words}} words, fewer when the table holds few points. Stop once the main contribution, every value and the picture are said: never add detail to use the room, as a shorter summary that says it all reads better than one that fills the space.

## How to write the context

The context summary isn't about behaviours or values: it gives the facts the review must take into account to read the period fairly, such as absences, changes of role, team or manager, responsibilities taken on or handed over, support given, a development plan or a promotion case. Say each fact once, even when several sources say it, the weightiest first. Name no company value and pass no judgement on the person: the context explains the period, the other two summaries weigh it. The rules above on how to write it, in the third person and in flowing paragraphs, still apply, but at about {{context_words}} words, fewer when there is little to say.
